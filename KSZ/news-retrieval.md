# 新闻与联网检索

## 行为与配置

新闻播报使用 `get_news_from_newsnow(source, detail, lang)`；娱乐圈等话题新闻、具体事件或人物的最新进展使用 `web_search(query)`。不新增搜索供应商或依赖。

| 请求 | 行为 |
| --- | --- |
| 未指定来源和类别 | 省略 `source`，先请求 `news_sources` 中第一个有效 NewsNow 来源；失败、超时或无结果时才使用默认 RSS |
| 指定来源 | 只请求该配置来源，失败后明确反馈 |
| 指定类别 | `source` 传类别，例如 `国际`；直接请求对应 RSS，不请求默认 NewsNow 来源 |
| 类别或来源未配置 | 明确反馈，不改播其他新闻 |
| 追问详情 | 同一工具设置 `detail=true`，使用本连接最近成功新闻的原链接 |
| 具体事件最新进展 | 使用 `web_search`，保留话题与时间范围 |

RSS 使用已有 `plugins.get_news_from_chinanews` 配置。`society_rss_url`、`world_rss_url`、`finance_rss_url` 分别提供社会、国际、财经类别；仅向模型声明非空且已配置的类别。默认备用源使用 `default_rss_url`，缺省为中新网社会 RSS。智控台模式需在该智能体的插件配置中提供这些字段，本地默认配置不会自动补入智能体私有配置。

保留 `source/detail/lang` 接口，`source` 的 Python 默认值由“澎湃新闻”改为空。未指定来源和类别时，模型必须省略该参数，不能主动填入默认来源，否则会按指定来源处理而不启用备用源。

最终工具描述兼容缺省值和原有模板文案，管理员自定义描述保持优先；每次生成工具描述时复制注册定义，不修改全局注册表。NewsNow 的 `source` 枚举仅含该连接已配置的有效来源及 RSS 类别，话题不作为来源提供。兼容旧的中新网工具，修正未配置类别回退社会新闻及错误的“科技”声明；两个新闻工具同时启用时，普通新闻与类别请求优先使用 NewsNow 工具。

新闻上下文保留实际来源、链接和可用发布时间，缺失发布时间明确标记未知。秘塔搜索结果保留检索问题、来源链接、日期及摘要，供模型核对事件与时间。事实边界提示禁止凭标题扩写、把无日期新闻称为今日新闻，或用相似活动推断目标事件的事实。

## Agent 路由配套

真实验收发现，当前普通环境的 Agent 会根据关键词预先决定是否保留工具。“百度热搜”及未包含“新闻”字样的具体事件查询可能在到达模型前被移除工具，单改工具描述无法解决。

`patches/agent-news-routing.patch` 增加热搜意图与联网查询意图，并以实际提供的 `web_search` 函数名判定可用性，避免仅在其他工具描述中提及 `web_search` 就误判其存在。沿用场馆、产品知识的优先级。话题误填来源而返回“未配置新闻来源或类别”时，仅保留 `web_search` 供续调；未启用搜索、禁用或强制选择工具、明确指定来源，以及已知来源或 RSS 类别未配置时不启用此分支。实际搜索结果续答仍禁用工具。

小智构建继续使用唯一 Compose 入口：

```bash
docker compose -f KSZ/compose.yml build xiaozhi-esp32-server
```

Agent 兼容镜像使用当前实例对应的基础镜像构建。以下示例与本次验收基础一致：

```bash
docker build -f KSZ/Dockerfile-agent \
  --build-arg AGENT_IMAGE=ghcr.io/apexlsai/museum_guide_agent:showroom \
  -t museum-guide-agent:news-retrieval-check .
```

构建阶段执行 `git apply --check`，基础版本不兼容时构建失败，不直接覆盖运行服务。Agent 仍由其所属项目现有的部署入口管理。此问题需要同时更新小智和 Agent；回退时分别恢复各自原镜像。

## ce:70 娱乐新闻兜底排查

2026-11-10 16:07:59，设备 `80:f1:b2:d4:ce:70` 询问“再看看娱乐圈的新闻”。16:08:01 模型调用 `get_news_from_newsnow(source="娱乐圈", lang="zh_CN")`，工具明确反馈来源或类别未配置，并建议话题使用 `web_search`。该设备未配置可用 RSS 类别。

实际入口为 `127.0.0.1:15000/v1`，对应 `museum_guide_agent_prod-1`、镜像 `ghcr.io/apexlsai/museum_guide_agent:0.1.6`。工具结果续答请求 `req_230b84341bb44270` 被判为 `tool_result`；Agent 向上游发送的工具数为 0，上游仍返回 1 次工具调用、0 字正文。Agent 抑制了该调用，16:08:03 设备播出“抱歉，模型暂时未返回可用内容，请稍后再试”。该次并未成功执行联网搜索。

第一轮验收使用另一个 Agent 实例，未覆盖该生产入口，因而没有发现工具提示后的续调被丢弃。本次同时收紧来源枚举，并在 Agent 增加上述受限搜索续调，覆盖流式和非流式返回。生产 `0.1.6` 与原验收基础版本均能应用补丁；最终生产版本构建及 Agent 专项 29 项、服务端回归 574 项通过。

使用 `ce:70` 的实际模型和插件配置创建独立对话：原生产入口回放同一工具错误，复现原兜底；生产版本修复副本接收原话后自动调用 `web_search`，回放错误工具结果时也能继续搜索并返回文字。证据及脱敏结果见[故障对照记录](logs/20261110_ce70-news-verification.jsonl)。记录中的 `chain_passed` 只评估调用、真实搜索和非空回复；搜索结果混有旧内容和娱乐传闻，未逐条核实事实。

最终镜像下的真实模型回归：娱乐圈原话 2.60 秒、错误工具结果回放 6.39 秒，均以 SSE 返回 `web_search` 调用和最终文字；另用原测试设备配置验证普通新闻 3.87 秒、指定百度热搜 3.58 秒、国际 RSS 2.15 秒、具体事件搜索 6.95 秒，四项路由均通过。六条结果及最终镜像 ID、补丁哈希保存在同一故障对照记录，耗时为单次样本。
