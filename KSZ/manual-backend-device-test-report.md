# 后端实体设备人工测试计划与交付报告

> 版本：v1.0dev  | 生成日期：2026-11-17  | 适用分支：`feature/ksz/direct-answer`

## 一、测试目标

验证设备从 OTA、鉴权、WebSocket/MQTT 建链、ASR、Agent、LLM、工具、TTS、视觉、语言/角色换绑、信标/定位、重连和异常恢复的完整后端闭环，形成可按设备证据交付的测试报告。测试只记录设备实际可观察结果和服务端可关联日志，不以“接口返回成功”替代设备听到、看到或实际执行。

## 三、执行前数据准备

1. 为本次测试准备专用测试用户和至少一台实体设备；设备绑定名称必须带语言后缀，例如 `儿童-汉语`。不要使用 `展厅` 这类无语言后缀名称验证正常切换；该名称只用于 BE-024 失败校验。
2. 在同一用户下准备目标智能体：儿童/青年/专家至少覆盖 `汉语、英语、日语、韩语`；需要测试测试环境时，再准备对应 `-测试` 智能体，确保名称唯一。
3. 记录每台设备 MAC、Client-Id、当前 agent_name、language、session_id。每次事件保留 request_id；语言/角色成功后等待自动重连，再验证实际语音。
4. 每项测试填写“实测结果、状态、缺陷单、执行人、执行时间、备注”。状态只使用：`通过`、`失败`、`阻塞`、`不适用`、`未执行`。

## 四、交付判定

- 88 个用例中，P0 用例全部通过；P1 失败项必须有缺陷单、风险评估和临时规避方案；P2 失败项需在报告中说明影响。
- 语言/角色/组合换绑必须同时满足：事件回执成功、manager-api 绑定与设备属性一致、设备自动重连、实体设备实际输出目标语言。
- 音频必须核对 `tts:start → 音频/字幕 → tts:stop`；只看到文本或控制消息不能判定设备播音通过。
- 视觉必须同时核对图片请求、回答、设备播报和打断/迟到结果隔离；HTTP `success=true` 不能单独作为通过依据。
- 交付包至少包含：本表、设备录像/录音、事件和请求日志、数据库/管理端关键快照、缺陷清单、已知限制。
